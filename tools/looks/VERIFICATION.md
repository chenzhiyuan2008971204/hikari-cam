# 攝影師風格驗證紀錄

## 方法

1. **參考照片**：從 GitHub 公開的作品集 repo 抓攝影師的作品，人工剔除書封、翻拍頁、拼貼、黑白混入等非照片內容。
   照片只在本機做統計，**不放進這個 repo**。
2. **對半驗證**：每位攝影師的照片分成兩半。A 半用來校正（`fit.py`），B 半完全不參與，只用來打分數，
   避免「校正自己背答案」。
3. **量什麼**（越小越接近）：
   - tone：明暗分布百分位的差距（% 顯示範圍）
   - cast：陰影、中間調、亮部的中性色偏差距（OKLab ×1000）
   - sat：整體飽和度差距（%）
4. **自我一致度（self）**：攝影師自己 A 半和 B 半之間的差距。濾鏡和 B 半的距離小於或接近 self，
   就代表已經跟攝影師「自己跟自己」一樣接近，再往下就量不出來了。
5. **只校正可靠的東西**：明暗曲線、色偏、整體飽和度。分色相飽和度在同一位攝影師的兩半之間可以差到兩倍
   （主要反映拍了什麼），所以不校正，維持依研究資料手調的設定。
6. **飽和度有偏差，加上限**：測試照片（Kodak 正片掃描）比一般照片飽和，參考照片多是印刷品翻拍，
   直接比會讓所有人都「該降飽和」，所以校正後的飽和度最多只能比研究值 ±0.2。
7. **乾淨畫面規則**（`build.py` 的 `CLEAN_LIMITS`）：校正結果一定要通過，不通過就由 `fit.make_clean`
   只退讓造成問題的那個參數。

重跑：

```bash
python3 verify.py 參考照片根目錄 --photos 測試照片 --iters 8 --write   # 每個風格一個子資料夾
python3 build.py                                                       # 烘焙 + 乾淨檢查
```

## 實用性檢查（全部 26 個通過）

- 乾淨畫面：白、92% 灰不偏色；白夠白、黑不發灰；三種膚色色相偏移 ≤ 12°、飽和度 0.65～1.7 倍；
  20% 灰保留 ≥ 0.06 亮度（暗部細節）；80%→95% 灰保留 ≥ 0.06 差距（亮部細節）
- 灰階漸層：黑到白嚴格遞增，沒有反轉
- 色相掃描：全色相 × 3 種飽和 × 3 種亮度，沒有斷層（實際畫面檢查：藍色漸層、黃色漸層、夕陽天空）
- 沒用來調校的照片：8 張未參與調校的照片上，沒有爆白、死黑或膚色偏移

這一輪修掉的引擎問題：
- 「白色保持乾淨」只看亮度，連飽和的檸檬黃也被洗淡 → 只對接近中性的像素生效
- 色域邊界在 OKLab 藍色附近會「出去、回來、再出去」，二分搜尋找錯邊界，連空濾鏡都在深藍出現鋸齒
  → 改成線性 RGB 的封閉解
- 被調亮的高飽和黃色只能褪成白色 → 飽和色往中灰收（犧牲一點亮度保留顏色，像底片）
